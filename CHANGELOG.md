## [v0.3.0] - 2026-08-22 ([`0ff65be`](https://github.com/grokify/godolt/commit/0ff65be))

### Highlights

- Server lifecycle helpers (`ServerReachable`, `StartServer`, `EnsureServer`) — start or reuse a local `dolt sql-server`, the shared pattern from visionstudio and omniroadmap
- `CreateDatabase` plus commit operations (`HasUncommittedChanges`, `AddAll`, `Commit`, `CommitAll`) for wrapping sync runs in a Dolt commit
- DSN helpers (`LocalDSN`, `EnsureParseTime`, `SplitDSN`) — pure string helpers for go-sql-driver DSNs pointed at a dolt sql-server, no driver dependency added

### Added

- `ServerReachable(addr)` probes a TCP address; `StartServer(dataDir, port)` launches `dolt sql-server` over a data directory and waits for readiness, caller owns the returned process; `EnsureServer(dataDir, port)` ensures one is serving, launching it detached if not — the shared local-server pattern from visionstudio and omniroadmap. Tests run against a real dolt server, skipping when the binary is absent ([`404f2dc`](https://github.com/grokify/godolt/commit/404f2dc))
- `CreateDatabase(ctx, db, name)` runs `CREATE DATABASE IF NOT EXISTS` over a server-wide connection ([`98b9d30`](https://github.com/grokify/godolt/commit/98b9d30))
- `Client.HasUncommittedChanges`, `Client.AddAll`, `Client.Commit`, `Client.CommitAll` — stage and commit working-set changes via `dolt_status`, `DOLT_ADD`, and `DOLT_COMMIT` (message bound as a parameter so it may contain any characters); `CommitAll` is a no-op on a clean working set, the pattern apps use to wrap sync runs ([`98b9d30`](https://github.com/grokify/godolt/commit/98b9d30))
- `LocalDSN(port, database)`, `EnsureParseTime(dsn)`, `SplitDSN(dsn)` — build the conventional local DSN, append `parseTime=true` for Ent, and split a DSN into its server-wide base and database name ([`2523fff`](https://github.com/grokify/godolt/commit/2523fff))

### Documentation

- README Library Features table extended with server lifecycle, DSN, and commit helpers, plus an application store pattern example (ensure server, create database, connect, wrap writes in a Dolt commit) ([`0ff65be`](https://github.com/grokify/godolt/commit/0ff65be))

## [v0.2.0] - 2026-08-17 ([`623fd1e`](https://github.com/grokify/godolt/commit/623fd1e))

### Highlights

- Fixed Client.Pull, which errored on every call since v0.1.0 — CALL DOLT_PULL returns a 3-column result the shared call() helper couldn't scan

### Breaking

- Client.Pull's return type changes from (string, error) to (*PullResult, error), exposing FastForward and Conflicts alongside the status message; there is no compatible old signature to preserve since every prior call errored unconditionally ([`623fd1e`](https://github.com/grokify/godolt/commit/623fd1e))

### Fixed

- Client.Pull now scans DOLT_PULL's actual (fast_forward, conflicts, message) result directly instead of assuming the 1-or-2-column shape shared by every other stored procedure; verified against a real dolt sql-server reproducing true history divergence ([`623fd1e`](https://github.com/grokify/godolt/commit/623fd1e))

## [v0.1.0] - 2026-08-16 ([`c7ec856`](https://github.com/grokify/godolt/commit/c7ec856))

### Highlights

- SQL-wire `Client` for remotes, push/pull/fetch, and active branch — zero added driver dependencies, the caller supplies the `*sql.DB`
- CLI-exec bootstrap (`Clone`, `InitDir`) and backup (`BackupAdd`, `BackupSync`, `BackupRestore`) operations for the cold path

### Added

- `New(db *sql.DB) *Client` wraps an existing connection to a `dolt sql-server` ([`c7ec856`](https://github.com/grokify/godolt/commit/c7ec856))
- `Client.RemoteAdd`, `Client.RemoteRemove`, `Client.Remotes` — register, remove, and list configured remotes via `CALL DOLT_REMOTE(...)` ([`c7ec856`](https://github.com/grokify/godolt/commit/c7ec856))
- `Client.Push`, `Client.Pull`, `Client.Fetch` — sync against a remote via `CALL DOLT_PUSH`/`DOLT_PULL`/`DOLT_FETCH` ([`c7ec856`](https://github.com/grokify/godolt/commit/c7ec856))
- `Client.ActiveBranch` — the connection's active branch via `SELECT active_branch()` ([`c7ec856`](https://github.com/grokify/godolt/commit/c7ec856))
- Argument validation (`quotable`) rejects characters that could escape a single-quoted SQL literal ([`c7ec856`](https://github.com/grokify/godolt/commit/c7ec856))
- `Clone(ctx, remoteURL, dir)` and `InitDir(ctx, dir, name, email)` — CLI-exec bootstrap operations for when no server exists yet ([`58c94f1`](https://github.com/grokify/godolt/commit/58c94f1))
- `Available()` reports whether the `dolt` CLI is on `PATH` ([`58c94f1`](https://github.com/grokify/godolt/commit/58c94f1))
- `BackupAdd`, `BackupSync`, `BackupRestore` — named backup targets, snapshot/sync, and restore; no `DOLT_BACKUP` stored procedure exists, so these are CLI-exec only ([`58c94f1`](https://github.com/grokify/godolt/commit/58c94f1))

### Documentation
